# Phase: Android — build, test on the real phone, upload to Play internal

Pre-checks (block with precise asks if missing): AdMob ids in facts (`admob_android_app_id`, `admob_android_banner`, `admob_android_interstitial`, `admob_android_rewarded`; also the iOS ones) — the owner pastes them in the thread, the bridge records them in facts. If absent → `blocked`, `blocked_on` = the AdMob checklist with exact values. Put the Android app id in app.json (plugin config) and the unit ids in `eas.json` `production.env` and in the EAS server-side env (`eas env:create`/`eas env:update` — OTA needs them there).

1. **Device build:** `eas build --local --platform android --profile preview` (APK, test ads) detached, per lingopath's `scripts/build-android.sh` safeguards (TMPDIR off tmpfs, 1 Gradle worker). `adb -s {{DEVICE}} install -r` it.
2. **Device test:** write `maestro/smoke.yaml` that walks `docs/testing.md`: launch, consent/onboarding, each core feature with the sample inputs, settings, kill + relaunch (state restored), screenshots at each step into `{{WORK_DIR}}/device/`. Run `maestro --device {{DEVICE}} test maestro/smoke.yaml`. Then **look at every screenshot yourself** (Read the PNGs) and judge: layout, truncation, dark mode, wrong numbers. Also `adb logcat` for crashes/ANRs during the run. Fix what you find, rebuild if needed (budget permitting), re-run. Don't tap test banners.
3. **Store build:** `eas build --local --platform android --profile production` → `store/play/{{SLUG}}-vc<N>.aab`; `~/git/common/scripts/verify-ad-ids.sh <aab> 3` must pass (never upload an ad-dark build). Back the EAS-managed upload keystore into `secrets/` (0400) — losing it means the app can never be updated.
4. **Upload:** `eas submit --platform android --profile production --path <aab> --non-interactive` to the **internal** track as a draft (the first API release must be a draft). If the Play app record / SA grant is missing (403 / app not found) → `blocked` with the exact console steps (app name, package `{{BUNDLE}}`, SA email). Then set the listing via the Play API where allowed (`scripts/play_listing.py` pattern from waterprep: texts, icon, feature graphic, screenshots, privacy URL).

Commit `maestro/`, `scripts/`, docs; keep the tree clean and pushed. Facts: `play_package` (`{{BUNDLE}}`), `android_vc`, `android_aab`, `device_test` (pass/fail + what was seen), `play_internal_release` (draft/complete), `upload_keystore_backup`.
